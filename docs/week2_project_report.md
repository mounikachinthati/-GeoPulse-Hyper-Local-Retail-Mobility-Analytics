GeoPulse – Week 2 Project Report

Hyper-Local Retail Mobility Analytics



1\. Introduction

During Week 2, the GeoPulse project progressed from data analysis to application development. The main focus was building a REST API, implementing automated testing, adding search and pagination, and developing an interactive analytics dashboard.



2\. Objectives

\- Develop a backend using FastAPI.

\- Connect the API with processed retail location data.

\- Implement automated API testing.

\- Add search, filtering, and pagination.

\- Develop an interactive Streamlit dashboard.

\- Visualize retail locations and category distributions.



3\. Work Completed



Day 8 – FastAPI Backend\*\*

\- Developed the FastAPI backend.

\- Connected the backend to the processed Guntur retail dataset.

\- Created endpoints for location retrieval and summary statistics.

\- Verified API functionality.



Day 9 – Automated API Testing\*\*

\- Implemented automated API tests.

\- Tested response status codes and endpoint functionality.

\- Validated request parameters and error handling.



Day 10 – Search and Pagination\*\*

\- Implemented retail location search.

\- Added retail-only filtering.

\- Added category-based filtering.

\- Implemented pagination using skip and limit.

\- Tested search and filtering combinations.



Day 11 – Interactive Dashboard\*\*

\- Developed an interactive dashboard using Streamlit.

\- Integrated the dashboard with the FastAPI backend.

\- Created KPI cards for total, retail, and non-retail locations.

\- Added search and filtering options.

\- Created category distribution charts.

\- Integrated an interactive geographic map using Plotly.

\- Added a retail location details table.

&#x20;5. Key Outcomes

\- Developed a functional REST API.

\- Implemented automated API validation and testing.

\- Added search, filtering, and pagination features.

\- Built an interactive analytics dashboard.

\- Connected backend data with dashboard visualizations.

\- Improved accessibility of retail location information.



&#x20;6. Challenges and Limitations

\- Backend and dashboard services must run separately.

\- Plotly map compatibility required adjustments.

\- The current dataset contains mapped places, not actual customer movement or transaction data.

\- Actual customer footfall and sales analysis require additional reliable datasets.



&#x20;7. Conclusion

Week 2 successfully transformed GeoPulse into an interactive retail analytics application. The FastAPI backend provides structured access to location data, while the Streamlit dashboard enables users to explore retail locations through KPIs, filters, charts, and geographic maps. The completed application provides a foundation for advanced spatial analytics in the next phase.
